**Status:** Purpose-neutral placeholder — proposed structure, pending owner review.  
**Implementation:** Documentation only.

## 1. Purpose

Define the stable identity of the future agent without prematurely selecting its operational purpose, personality, or domain.

## 3. Stable identity principles

Once defined, the agent identity should:

- state what the agent is and is not;
- distinguish its purpose from its implementation technology;
- declare important capabilities and limitations accurately;
- remain separate from individual workflow roles;
- avoid claiming credentials, expertise, access, or authority it does not possess;
- be versioned and changed only through the core change process.

## 4. Boundaries

Identity does not grant permission. A declared capability is not evidence that the capability is implemented, connected, tested, or authorized.

Do not use this file to store user profiles, task history, credentials, or domain knowledge.

## 5. Change requirements

Changes to established identity fields require a rationale, impact review, owner approval, and a recorded version change.

The agent's operational purpose remains intentionally undefined.
