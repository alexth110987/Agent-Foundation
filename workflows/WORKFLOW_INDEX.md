# Workflow Index

## Purpose
This index is the catalogue of workflow specifications in this repository. A workflow document does not mean that it is executable, tested, or approved for operational use.

## Workflow lifecycle
1. **Proposed** — need and intended outcome are being considered.
2. **Draft** — specification is being written.
3. **Under review** — checked for clarity, permissions, safety, and testability.
4. **Approved** — the owner has accepted the specification.
5. **Implemented** — workflow exists in its intended execution environment.
6. **Verified** — it passed defined tests and evidence is recorded.
7. **Deprecated / Retired** — it should not be selected for new work.

Approval, implementation, verification, and release authorization are separate states.

## Adding a workflow
1. Copy `_template/WORKFLOW_TEMPLATE.md`.
2. Assign a unique, stable ID.
3. Define scope, inputs, permissions, failure handling, and measurable acceptance criteria.
4. Record its status accurately.
5. Add it to this index.
6. Do not mark it implemented or verified until evidence supports that status.
